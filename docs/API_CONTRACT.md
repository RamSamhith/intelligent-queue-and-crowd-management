## 1. Overview & Architectural Boundaries

VisionQueue exposes a unified, high-performance REST and WebSocket interface for live state ingestion, historical telemetry retrieval, and CV pipeline lifecycle management.

### Key Operational Guarantees
- **Live Stream Frequency:** WebSocket delivers live state packets at ~25–30 Hz matching the CV pipeline processing loop.
- **Atomic State Consistency:** Every message emitted across REST and WebSocket is sourced from the unified, thread-safe `LiveState` coordinator snapshot.
- **Privacy & Anonymous Tracking:** Track IDs (`track_id`) are ephemeral, integer-based session identifiers generated by ByteTrack. **No biometric recognition, facial template extraction, or cross-session re-identification is performed.**
- **Single Source of Truth:** The pipeline lifecycle (`START`, `STOP`, `RESET`) is orchestrated via `CVService`, ensuring thread safety and clean database session delineation.

## 2. Server Base URL & Transport

- **REST API Base URL:** `http://<HOST>:<PORT>/api/v1`
- **Health Check Base URL:** `http://<HOST>:<PORT>/health`
- **WebSocket Base URL:** `ws://<HOST>:<PORT>/ws`

CORS is enabled by default for all standard origins (`*` or configured origins).

## 3. REST API Endpoints

### 3.1 Health & Diagnostics

#### `GET /health`
Returns the liveness of the API process itself. Does not evaluate CV pipeline state.

- **Response:** `200 OK`
```json
{
  "status": "ok"
}
```

#### `GET /api/v1/status`
Returns high-level pipeline operational health, camera connection status, vision subsystem health, and performance telemetry.

- **Response:** `200 OK`
```json
{
  "system_state": "LIVE",
  "camera_state": "ONLINE",
  "is_healthy": true,
  "is_frozen": false,
  "status_reason": "Operational",
  "performance": {
    "processing_fps": 29.8,
    "inference_latency_ms": 13.8,
    "frame_age_ms": 14.2
  },
  "vision": {
    "person_detection": "ACTIVE",
    "face_detection": "DISABLED",
    "tracking": "ACTIVE"
  },
  "active_model": "yolo26m_crowd.onnx",
  "execution_provider": "CUDAExecutionProvider",
  "is_gpu": true,
  "persistence_healthy": true,
  "pipeline_running": true,
  "last_frame_timestamp": 1740307200.123
}
```
- **Error Response:** `503 Service Unavailable` if pipeline has not started or produced state yet.

### 3.2 Live Subsystem Telemetry

#### `GET /api/v1/live`
Returns the complete unified `LiveState` packet matching the WebSocket streaming payload.

- **Response:** `200 OK` (Schema documented in [Section 4.1](#41-live-state-packet-schema-wslive))
- **Error Response:** `503 Service Unavailable` if pipeline has not produced state yet.

#### `GET /api/v1/counts`
Returns current occupancy, cumulative session counting, and directional entry/exit metrics.

- **Response:** `200 OK`
```json
{
  "current": 4,
  "track_instances": 12,
  "unique_session_approx": 12,
  "entries": 8,
  "exits": 4,
  "net_count": 4
}
```
*Note on Terminology:* `current` indicates active people detected in the monitored zone. `track_instances` represents unique track trajectories observed this session.

#### `GET /api/v1/occupancy`
Returns capacity configuration and current capacity percentage utilization.

- **Response:** `200 OK`
```json
{
  "capacity": 25,
  "capacity_state": "NORMAL",
  "percent": 16.0
}
```
*Note:* If capacity is not configured (`capacity = null`), `percent` returns `null` and `capacity_state` is `"NORMAL"`.

#### `GET /api/v1/crowd`
Returns crowd density analytics, qualitative crowd levels, smoothed trends, and peak records.

- **Response:** `200 OK`
```json
{
  "level": "LOW",
  "raw_level": "LOW",
  "trend": "STABLE",
  "peak_count": 9,
  "peak_occupancy_percent": 36.0,
  "peak_timestamp": 1788696000.123
}
```

#### `GET /api/v1/alerts`
Returns currently active or recent alerts generated by the P0 alert engine.

- **Response:** `200 OK`
```json
[
  {
    "id": "alert_crowd_surge_1788696010",
    "type": "CROWD_SURGE",
    "severity": "WARNING",
    "fired_at": 1788696010.5,
    "cleared_at": null,
    "status": "ACTIVE",
    "reason": "Rapid crowd influx detected over 5.0s window"
  }
]
```

#### `GET /api/v1/tracks`
Returns current active tracks with bounding box coordinates and detection confidences.

- **Response:** `200 OK`
```json
[
  {
    "track_id": 104,
    "bbox": [120.5, 84.0, 65.0, 182.0],
    "confidence": 0.88
  }
]
```
*Bounding Box Format:* `[x, y, width, height]` in pixel coordinates relative to the source frame.

### 3.3 Pipeline Lifecycle Management

#### `POST /api/v1/pipeline/start`
Starts camera acquisition, detection, tracking, and background persistence worker.
- **Idempotent:** Calling when already running returns `200 OK` (`"Pipeline was already running."`).
- **Response:** `200 OK`
```json
{
  "status": "ok",
  "message": "Pipeline started."
}
```

#### `POST /api/v1/pipeline/stop`
Stops background worker thread, drains pending persistence queues, closes camera source, and marks active session as `STOPPED` in the database.
- **Idempotent:** Calling when already stopped returns `200 OK` (`"Pipeline was already stopped."`).
- **Response:** `200 OK`
```json
{
  "status": "ok",
  "message": "Pipeline stopped."
}
```

#### `POST /api/v1/pipeline/reset`
Resets session counts, tracking state, analytics history, alerts, and reliability metrics. If running, finalizes the active DB session and initializes a clean new session record.
- **Error Response:** `503 Service Unavailable` if called while the pipeline is stopped (`"Cannot reset: pipeline is not running."`).
- **Response:** `200 OK`
```json
{
  "status": "ok",
  "message": "Pipeline session reset."
}
```

### 3.4 Historical Data & Analytics Query

#### `GET /api/v1/sessions`
Returns paginated list of recorded sessions.

- **Query Parameters:**
  - `limit` (int, default=100, max=1000)
  - `offset` (int, default=0)
- **Response:** `200 OK`
```json
[
  {
    "id": "sess_89f029bc_20260906",
    "camera_id": "cam_default",
    "started_at": "2026-09-06T11:00:00Z",
    "ended_at": "2026-09-06T11:45:00Z",
    "status": "STOPPED"
  }
]
```

#### `GET /api/v1/sessions/{session_id}`
Returns details for a specific session ID. Returns `404 Not Found` if missing.

#### `GET /api/v1/history`
Returns time-series measurement telemetry (crowd levels, counts, occupancy, latency) for a session.

- **Query Parameters:**
  - `session_id` (string, required)
  - `limit` (int, default=100, max=1000)
  - `offset` (int, default=0)
- **Response:** `200 OK`
```json
[
  {
    "id": 1,
    "session_id": "sess_89f029bc_20260906",
    "recorded_at": "2026-09-06T11:00:05Z",
```

#### `GET /api/v1/history/events`
Returns entry/exit crossing events and queue state change events.

- **Query Parameters:**
  - `session_id` (string, required)
  - `limit` (int, default=100, max=1000)
  - `offset` (int, default=0)
- **Response:** `200 OK`
```json
[
  {
    "id": 1,
    "session_id": "sess_89f029bc_20260906",
    "event_type": "ENTRY",
    "occurred_at": "2026-09-06T11:00:10Z",
```

#### `GET /api/v1/history/alerts`
Returns fired and cleared alerts for audit and reporting.

- **Query Parameters:**
  - `session_id` (string, required)
  - `limit` (int, default=100, max=1000)
  - `offset` (int, default=0)

## 4. WebSocket Streaming Protocol

### 4.1 Live State Packet Schema (`/ws/live`)

Connected clients receive real-time JSON packets at ~25 Hz:

```typescript
interface LiveStatePacket {
  schema_version: 1;
  timestamp: number;          // Unix epoch in seconds (float)
  session_id: string;         // Unique session UUID
  frame_id: number;           // Monotonically increasing frame sequence
  system_state: "HEALTHY" | "DEGRADED" | "CRITICAL" | "OFFLINE" | "STOPPING";
  camera_state: "CONNECTED" | "DEGRADED" | "DISCONNECTED" | "ERROR";
  performance: {
    processing_fps: number;
    inference_latency_ms: number;
    frame_age_ms: number;
  };
  vision: {
    person_detection: "HEALTHY" | "DEGRADED" | "FAILED" | "DISABLED";
    face_detection: "HEALTHY" | "DEGRADED" | "FAILED" | "DISABLED";
    tracking: "HEALTHY" | "DEGRADED" | "FAILED" | "DISABLED";
  };
  counts: {
    current: number;                // Instantaneous people in monitored zone
    track_instances: number;        // Unique track trajectories this session
    unique_session_approx: number;  // Backwards-compatible alias
    entries: number;                // Cumulative line-crossing entries
    exits: number;                  // Cumulative line-crossing exits
    net_count: number;              // Cumulative entries minus exits
  };
  occupancy: {
    capacity: number | null;        // Maximum capacity (null if unconfigured)
    capacity_state: "NORMAL" | "APPROACHING" | "AT_CAPACITY" | "EXCEEDED";
    percent: number | null;         // Occupancy percentage (null if no capacity)
  };
  crowd: {
    level: "LOW" | "MODERATE" | "HIGH" | "CRITICAL";
    raw_level: "LOW" | "MODERATE" | "HIGH" | "CRITICAL";
    density_score: number;          // 0.0 to 1.0 normalized density
    trend: "INCREASING" | "DECREASING" | "STABLE";
    is_elevated: boolean;
    peak_count: number;             // Peak people count seen this session
    peak_occupancy_percent: number | null;
    peak_timestamp: number | null;
  };
  alerts: Array<{
    id: string;
    type: "OVER_CAPACITY" | "RAPID_SURGE" | "CAMERA_FAILURE" | "CROWD_SURGE" | "DENSITY_SPIKE" | "QUEUE_BACKLOG";
    severity: "INFO" | "WARNING" | "CRITICAL";
    fired_at: number;
    cleared_at: number | null;
    status: "ACTIVE" | "CLEARED";
    reason: string;
  }>;
  status_reason: string;
  is_healthy: boolean;
  is_frozen: boolean;
  detections_count: number;
  tracks_count: number;
  faces_count: number;
  queue_people: number;             // Dedicated queue ROI people count
}
```

### 4.2 Lightweight Tracks Stream (`/ws/tracks`)

For lightweight HUD overlays and low-bandwidth clients:

```typescript
interface TracksPacket {
  frame_id: number;
  timestamp: number;
  tracks: Array<{
```

## 5. Standard Enums Reference

| Enum | Possible Values | Meaning / Usage |
| :--- | :--- | :--- |
| `SystemState` | `HEALTHY`, `DEGRADED`, `CRITICAL`, `OFFLINE`, `STOPPING` | Overall system health status. |
| `CameraHealthState` | `CONNECTED`, `DEGRADED`, `DISCONNECTED`, `ERROR` | Camera feed connectivity and acquisition status. |
| `CapacityState` | `NORMAL`, `APPROACHING`, `AT_CAPACITY`, `EXCEEDED` | Capacity utilization relative to thresholds (e.g. approaching at 80%). |
| `CrowdLevel` | `LOW`, `MODERATE`, `HIGH`, `CRITICAL` | Quantized crowd density level. |
| `Trend` | `INCREASING`, `DECREASING`, `STABLE` | Temporal crowd trend over the configured window. |
| `AlertSeverity` | `INFO`, `WARNING`, `CRITICAL` | Severity level for UI color coding and notification priority. |
| `AlertStatus` | `ACTIVE`, `CLEARED` | Lifecycle status of an alert. |

## 6. Frontend Integration Example (TypeScript / WebSockets)

```typescript
export class VisionQueueClient {
  private ws: WebSocket | null = null;
  private reconnectIntervalMs = 2000;

  constructor(
    private url: string,
    private onState: (state: LiveStatePacket) => void,
    private onError?: (err: Event) => void
  ) {}

  public connect(): void {
    this.ws = new WebSocket(this.url);

    this.ws.onmessage = (event: MessageEvent) => {
      try {
        const packet: LiveStatePacket = JSON.parse(event.data);
        this.onState(packet);
      } catch (err) {
        console.error("Failed to parse LiveState packet:", err);
      }
    };

    this.ws.onerror = (err) => {
      if (this.onError) this.onError(err);
    };

    this.ws.onclose = () => {
      // Auto-reconnect on server restart or disconnect
      setTimeout(() => this.connect(), this.reconnectIntervalMs);
    };
  }

  public disconnect(): void {
    if (this.ws) {
      this.ws.close();
      this.ws = null;
    }
  }
}
```
